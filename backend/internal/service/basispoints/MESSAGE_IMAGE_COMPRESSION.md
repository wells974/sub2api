# 普通消息历史图片压缩

## 开关与范围

新增环境变量 `SUB2API_BPS_MESSAGE_IMAGE_COMPACT`，默认未设置/`false`，开启为
`true`。非法值沿用图片设置错误出口。无新增管理员 DTO、数据库字段或依赖。
需要现有图片功能启用、`excel_bps_image_limit_policy=auto_compact`，以及稳定的
会话身份和可用历史状态缓存。支持 native 和 HTTPS relay 图片准备路径。

未开启且会话没有新检查点时，保持原请求、错误、裁剪、自动压缩、上传和用量
行为；不创建图片变换缓存。仅配置开关不会放宽图片数量、单图大小或总预算。
本功能不改变 New API/代理入站请求体上限。

## 处理顺序

1. 按顺序重放已有历史检查点。
2. 仅当可测的图片总字节或单图字节超过实际预算时，尝试普通消息历史图片压缩。
   数量超限由原有策略处理，图片重编码不会减少数量。
3. 使用原有进度匹配/尾部结构识别历史边界，再收紧到最近一组连续用户消息的
   起点。该用户回合中的全部消息和图片均保留，不能把同一回合的早期截图当成
   旧历史。边界不明确、没有历史或受保护部分本身超限时不变换图片。
4. 只处理历史普通消息的内联 `input_image`；工具结果、系统/开发者消息、URL、
   file_id 及未知结构不处理。先对较大的历史图片进行像素不变的 PNG 重编码，
   若仍不够，再用固定 v1 参数：长边不超过 2048、JPEG 质量 85；透明图使用 PNG。
   不放大小图，不删除图片或消息，不改文本、角色、顺序、detail、工具参数和调用关系。
5. 只接受字节数减少的结果。目标为总预算的 75%，实际硬限仍按现有校验。
   单次最多 64 次变换尝试，小于 256 KiB 的图片保持原样。
6. 保存摘要检查点成功后才应用变换；CAS 失败在上传/生成前返回原有中性错误。
   随后接回旧工具截图裁剪、自动历史压缩和原有完整媒体验证。

PNG 动画、ICC/EXIF/gamma/chromaticity 元数据、JPEG APP1–APP15 元数据和
GIF/WebP 当前保守跳过；16 位 PNG 不进行有损变换。避免丢动画、错误旋转、
透明背景变黑或静默降低高位深度。PNG sRGB 标记不阻止处理。

降采样可能影响截图小字、细线和 OCR。需要清晰度的本轮原图保持逐字节不变。
不保证所有历史均可压入预算；未知/不支持的图片仍交给原校验，而不是冒充有效
图片或绕过限制。显式 compact 不启动新图片变换，但会重放已有变换。

## 缓存与历史一致性

`MessageImageCache` 是独立的进程内缓存，key 包含会话隔离范围、原始 data URL
内容 SHA-256、变换版本和模式。不保存原图；只缓存变换后的编码图片或固定的
跳过原因。最多 128 项、编码图片字符串总量 64 MiB、TTL 30 分钟；访问时清理
过期项，容量不足淘汰最久未使用项。无磁盘、外部下载或新增后台 goroutine。

缓存命中省去图像解码/缩放/重编码，后续原生附件缓存还能复用附件 ID。
同一结果不会重复有损压缩；修改处理算法必须使用新版本，保留旧版重放能力。
这是图片变换缓存，不是模型 Token 缓存，不能保证模型缓存命中。

历史状态只增加 `MessageImages` 检查点：位置、参数、前缀摘要和结果摘要。
不向 Redis 保存图片、URL、文本或工具参数。原客户端历史再次传入时，先按
检查点恢复相同图片表示，再处理后续 trim/compact 检查点。冷缓存/进程重启后
可从请求中的原图重建，结果摘要不一致则失败，不静默改变已接受的历史。
相邻图片压缩检查点只有在重放验证一致后才合并，避免每一轮都增加一项。

关闭开关会停止新变换，但已有检查点仍会重放，和旧工具截图裁剪的回退语义一致。
检查点遵守原有容量限制，且为后续历史压缩预留一项。显式 compact 沿用原有
检查点清理行为。直接降级到不认识 `MessageImages` 的旧二进制不能保证继续旧
会话；应先完成会话压缩或保留包含此重放模块的版本，而非手工清空 Redis。

## 资源与取消

进程内最多一个图像解码/变换任务；等待者遵循 context 取消，获得执行权后
再次查缓存，避免并发重复解码。每张源图最多 20 MiB、16 Mi 像素，解码前检查
尺寸；编码输出必须小于源图，缓存以外还有当前图像和请求本身的内存开销。

新压缩与检查点重放分别使用 10 秒协作式时间预算。解码读取、编码写入、各阶段
之间检查 context；单次底层缩放/编解码 CPU 操作不能强制中断，故不是严格墙钟
超时。不会起一个后台 worker 然后放弃等待。新压缩超时放弃未提交的变换，继续
原预算策略；已有检查点重放失败必须报错。请求取消不会提交新检查点。
