v2.21.5.4：补齐 BPS 自动授权失败诊断

修复 BPS 首次自动授权任务执行失败时，Worker 丢弃失败原因、后台仅返回 `failed`、页面只显示通用错误的问题。本版用于继续定位实际登录故障，不代表已解决所有自动授权失败。

## 诊断改进

- 配套登录运行包上报预定义的失败原因和执行阶段，覆盖运行包异常、网络连接失败、密码拒绝、2FA 拒绝、额外验证、授权回调及令牌校验失败等情况。
- 后台首次登录队列保存并返回 `error_code`、`error_stage`，页面显示对应原因、阶段和处理提示。
- 错误码和阶段采用白名单，未知错误归为通用失败；原始上游输出、密码、2FA 密钥和 Token 不进入诊断字段或任务错误日志。
- 继续兼容旧 Worker 和没有诊断字段的响应，保留普通 2FA、BPS 手动授权、自动导入及失败重试流程，无需数据库迁移。

## 配套运行包与升级

主程序、前端和登录运行包必须一起发布为 `2.21.5.4`。只更新页面或主程序，无法补回旧 Worker 已丢弃的失败原因。

完整发布包含应用程序包、`checksums.txt` 及以下两个运行包：

- `sub2api-reauth_2.21.5.4_linux_amd64.tar.gz`
- `sub2api-reauth_2.21.5.4_linux_arm64.tar.gz`

两个运行包从同一发布提交构建，包含新的 Worker 诊断代码；发布后须具备 GitHub SHA-256 digest，主程序仍会校验下载内容。使用完整 Release 流程，保持 `simple_release=false`，仓库变量 `SIMPLE_RELEASE` 也不能为 `true`。

内置运行器会按新版本下载运行包；等待“凭证运营”的授权服务就绪后，再进行一次 BPS 自动授权，查看具体失败原因和阶段。使用独立 Worker 的部署需要同步更新 Worker。升级前已经失败或被清理的任务无法追溯恢复诊断信息。

## 验证范围

诊断修复已通过后端定向竞态测试、前端 141 项回归、类型检查、ESLint 和生产构建；Python 测试 95 项通过、1 项 Linux 专属测试在 macOS 跳过。新增测试使用固定版本的真实登录程序及离线 HTTP 边界，覆盖完整授权成功、密码拒绝、2FA 拒绝、网络失败、安全验证和错误回调。线上已确认任务创建成功后进入失败状态；真实失败根因仍需升级配套诊断版后复现确认。

本次发布准备另已通过 17 项发布脚本测试及内嵌前端的主程序构建，版本输出为 `2.21.5.4`。amd64、arm64 运行包均完成本地构建，各自通过包内 114 项 Python 测试、Node 流程测试及 Alpine、Ubuntu 便携性检查，并核对打包 Worker 与当前诊断修复源码一致。
