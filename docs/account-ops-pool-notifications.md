# 号池状态通知扩展

入口：**智能运维 → 账号运维 → 通知设置 → 号池状态通知**。

先配置邮件或 Webhook 通道，再开启「启用账号提醒」总开关和「启用号池通知」。默认关闭号池通知，已有用户升级不会自动收到新增推送。

两个独立选项：

- **账号状态变化**：账号异常、凭证失效、重登失败、恢复可用，以及调度状态、账号增删变化。可用数不变时也能通知，例如一个账号恢复、另一个账号失效。
- **可用数 / 总数变化**：首次启用发送当前数量；后续只在观察到数量变化时发送。

所有号池通知均附带当前可用数 / 总数，以及存在时的变更前数量。一次检查合并成一条消息，最多列出 10 个账号变化，其余显示数量。完整账号状态仍保存在比较快照中，下一次不会重复报告被省略的账号。

示例：

```text
号池状态变更
可用 / 总数：18 / 20
变更前：19 / 20
账号 A (#42)：可用 → 凭证失效；重登失败
检测时间：2026-11-11 15:30:00 CST
```

## 通道与 Bark

复用账号运维已有的邮件、企业微信、钉钉、飞书、自定义 Webhook，以及通道加密、测试、历史记录、发送限流与分通道重试。

Bark 使用现有 **自定义 Webhook**：

```text
URL: https://api.day.app/你的设备Key
```

```json
{"title":"{{title}}","body":"{{message}}","group":"Sub2API"}
```

设备 Key 放在加密保存的 URL 中，不要写进明文 JSON 模板。也可使用符合现有 Webhook 安全规则的自建 HTTPS Bark 服务。保存后可以通过原有「测试」按钮验证通道；号池扩展没有自己的发送接口或 Bark 密钥。

## 统计与恢复口径

- 统计全部平台未删除的母账号；停用账号计入总数，影子账号不重复计数。
- 可用性复用 `Account.IsSchedulable()`，包括启停、过期、限流、过载、临时冷却和账号配额，并读取性能守护 / AI 运维暂停状态。
- 凭证运营 V2 记录存在时优先采用 V2 的探测结果，即使该账号暂停了 V2 自动任务；否则采用旧凭证守护结果。
- 已确认鉴权失败后，后续网络错误不会清空失效状态。重登成功本身也不会覆盖仍失效的探测结果。
- 读取 Codex 重登终态，排除其他 OAuth profile 与 TOTP 轮换任务。比失败重登更新的成功探测会清除过时的重登失败标记。
- 「可用」不表示一定满足指定模型权限、实时并发或其他请求级调度约束。

复用账号运维共享任务的约 15 秒轮询。通知描述的是采样时的状态，两个采样之间发生又消失的短暂变化可能不会被捕获。重试消息保留原检测时间，便于区分当前状态与延迟送达的历史变化。

## 结构与上游合并

新增逻辑集中在独立文件，不修改凭证守护、凭证运营、网关请求处理、账户更新流程、路由或依赖注入。

| 文件 | 职责 |
| --- | --- |
| `backend/internal/service/account_ops_pool.go` | 配置扩展、状态比较、可用数计算、通知格式、扫描入口 |
| `backend/internal/repository/account_ops_pool.go` | 只读状态查询、跨实例串行化、快照与事件原子入队、关闭后的取消 |
| `backend/migrations/336_account_ops_pool_notifications.sql` | 独立快照表、队列事件类型扩展、重登记录查询索引 |
| `frontend/src/api/admin/accountOpsPool.ts` | 类型及现有 scoped settings API 的封装 |
| `frontend/src/components/admin/operations/AccountOpsPool*.vue` | 独立设置卡片和记录展示 |
| `frontend/src/i18n/locales/{zh,en}/accountOpsPool.ts` | 独立语言资源 |

必须保留的少量接入点：

1. `account_ops.go`：配置字段、新事件类型允许判断、共享定时任务里的一次扫描调用。
2. `account_ops_config.go` / `account_ops_scoped.go`：详情字段、配置保存与兼容处理。老客户端省略扩展字段时保留已有配置；更新号池设置不会覆盖通道和余额规则。
3. `account_ops_notification.go`：消息格式分派。发送、重试、租约和通道回执逻辑直接复用原实现。
4. repository 的 `account_ops.go` / `account_ops_once.go`：号池独立关闭处理，以及避免阈值规则清理错误取消号池事件。
5. 前端 `AccountOpsView.vue`、API 类型和语言资源入口：挂载组件、保留配置字段、新事件显示。

数据库迁移沿用项目的不可变迁移规则。合并上游新增迁移时检查文件顺序；已部署的迁移不能改内容或重命名。

## 持久化与验证

锁顺序与原配置更新保持一致：配置 advisory lock → 号池快照 → 事件队列。取得锁后重新读取配置和账号状态；不会让旧配置扫描在关闭通知后重新入队。快照更新与新增事件在同一事务里提交，外部通知发送不占用这个事务。

每次变化写入现有 `account_ops_threshold_events` 的不可变事件，使用独立的 `account_pool` 类型。数据库租约和分通道回执复用原逻辑：同一事件成功的通道不参与失败重试，失败通道最多尝试 3 次。进程恰好在外部发送成功、回执持久化之前崩溃时，仍有重复投递的可能，这是现有通知通道的交付边界。

关闭总开关或号池扩展会取消待发号池事件并清除比较基线；重新启用按首次观察处理。状态/数量选项控制后续生成的新事件，已入队的历史消息保留原始内容。

测试覆盖：状态/数量变化、鉴权失败后 transient、恢复、性能暂停、账号删除、旧客户端配置兼容、消息转义、Bark 模板、分通道重试，以及真实 PostgreSQL 中的并发去重、回滚、重启、配置关闭、V2 优先、TOTP 排除与影子账号排除。
